1. THE CORE DECISION — read this before writing any CSS
--------------------------------------------------------------------------------
Lenis.dev is a MARKETING SITE. Its motion is SCROLL-driven: you scroll, the hand
turns. Beautiful, and wrong for us.

We are not a marketing site. We are an agent that DOES things. So our motion must
be STATE-driven: the agent listens, thinks, verifies, refuses, sends — and the
screen reacts to THAT, not to the scrollbar.

    Scroll-driven  = "look how cool this site is"
    State-driven   = "look what this agent just did"   <- this wins the demo

Keep Lenis for feel (it's 3kb, one line, makes everything smoother). But the
signature moment is the AGENT STATE MACHINE, not a scroll sequence.

THE THESIS THAT MAKES ANIMATION LEGITIMATE ON AN ACCESSIBILITY APP:
  One event stream drives BOTH the voice and the visuals. Same state change
  fires the ElevenLabs line AND the animation, at the same moment.
    - blind users get the audio
    - LOW-VISION users (most of our users) get big, high-contrast motion cues
    - sighted judges get the show
  Say this sentence in the pitch. It turns "pretty animations" into an
  accessibility argument, which is the whole difference between a nice UI and a
  UI that wins a prize on THIS project.

NON-NEGOTIABLE: prefers-reduced-motion must kill or flatten everything. Vestibular
disorders are a disability. Failing that check on an accessibility app is the one
mistake a judge will actually punish us for.


2. THE HAND-MODEL EQUIVALENT — our signature object
--------------------------------------------------------------------------------
Lenis's hand is a 3D WebGL model (Three.js / R3F). NOT achievable in 10 hours on
top of voice + agent loop. Don't try.

Our equivalent, and honestly a better fit: THE VOICE ORB.
A single SVG/canvas object, centre of the screen, driven by REAL audio amplitude
from a Web Audio AnalyserNode. Five states, each visually distinct:

  idle       slow breathing pulse, dim
  listening  deforms live to the user's mic amplitude
  thinking   slow orbit / shimmer, no amplitude
  speaking   deforms to the ElevenLabs output amplitude
  REFUSING   hard stop, desaturate, red ring, sharp shake — then still

The refusing state is the one nobody else will have. It is the ANS story made
visible. Build it last but do not cut it.

[ ] orb component with 5 states
[ ] wired to real mic amplitude (AnalyserNode)
[ ] wired to real TTS output amplitude
[ ] every state also announced via aria-live
[ ] reduced-motion: states become colour/text changes, no movement

5. THE VIBE — LOCKED. Do not re-litigate.
--------------------------------------------------------------------------------
MINIMALIST. Two base colours, two signal colours, one display face. That's all.

PALETTE (contrast-checked, real numbers)
  --paper    #eef4ed   SURFACE. The background, everywhere.
  --ink      #0b2545   TEXT. Body, headings, borders, icons.
  --success  #3b6064   resume parsed, job sent, employer verified, task done
  --failure  #8c2f39   parse failed, application rejected, verification refused

  Measured against #eef4ed:
    ink      13.77:1   AAA
    success   6.18:1   AA
    failure   7.28:1   AAA
  All pass. This palette is accessible AS GIVEN — on a light surface.

*** WHY LIGHT AND NOT DARK ***
  Both signal colours are dark, so on a #0b2545 background they collapse:
    success on navy  2.23:1  FAIL
    failure on navy  1.89:1  FAIL
  Unusable, and on an accessibility app that's the one thing judges punish.
  So: PAPER IS THE SURFACE, INK IS THE TEXT. It also suits Forum better —
  a Roman-inscription serif wants paper, not a terminal.

  IF you ever need a navy section (a hero band, a footer), use these tints:
    success on navy  #7a9494  (4.76:1)
    failure on navy  #b8888a  (5.08:1)
  Don't use the base accents on navy. Ever.

TYPE — Forum on EVERYTHING (decided), and the caveats
  Every element on the page uses Forum. Inter has been removed.
  *** FORUM SHIPS ONLY WEIGHT 400. THERE IS NO BOLD. ***
  So hierarchy comes from SIZE, LETTER-SPACING and COLOUR, never font-weight.
    - big headings: Forum, generous letter-spacing, full ink
    - de-emphasis: same size, ink at 60% opacity — not a lighter weight
  *** FORUM ALSO HAS NO ITALIC. *** The hero's bold+italic is SYNTHESIZED by
  the browser (faux weight + oblique slant). It holds up at 56px. Do not use
  synthesized bold/italic below ~32px — it turns to mush.
  Because Forum is spindly at UI sizes, small text is nudged UP and tracked
  wider (body 16, labels 12.5 at .18em, rows 14). Do not shrink these back.
  Scale: 12.5 / 14 / 16 / 17 / 20 / 40 / 56.

SHAPE
  Radius 0 everywhere. Sharp edges, no exceptions.
  NO WHITE. Cards are the same colour as the page (--surface = --paper);
  separation comes from a 1px hairline, never a fill or a shadow.

THE REST
  [ ] SPACING   8px grid, no exceptions
  [ ] RADIUS    pick one (8px) and never vary it
  [ ] BORDERS   1px ink at 12% opacity — minimalism means lines, not shadows
  [ ] SHADOWS   basically none. If you need depth, use a border.
  [ ] FOCUS     2px ink ring, visible on everything, never removed
  [ ] MOTION    colour transitions between ink/success/failure carry meaning;
                success and failure must ALSO differ by icon + text, never by
                colour alone (colour-blind users)

Lock all of this in one tokens file. Every later page imports it and adds
nothing new. If a page needs a fifth colour, the answer is no.
